## Why This Matters To blar

`../blar` expands containers before recompressing their payloads with stronger
compression. ZIP-based formats are the largest immediate target: Office Open
XML, EPUB, JAR, APK, ODT, plain ZIP, and similar formats.

For those files, the archive-time path should:

1. Extract each embedded raw DEFLATE stream.
2. Inflate it to raw bytes.
3. Identify the encoder fingerprint/config that best reproduces the original
   stream.
4. Store the raw bytes under blar's stronger compression, plus the compact
   fingerprint/config.
5. If reproduction is not byte-exact, store a small `../difz` residual patch.

The extract-time path should:

1. Decode blar's stored raw bytes.
2. Recompress with the stored fingerprint/config.
3. Apply any difz residual patch.
4. Rebuild the outer container byte-identically.

That makes this repo less a "fingerprint lookup table" and more a configurable
DEFLATE reproduction engine with attribution as a required API.

| ID | Family / behavior |
|---:|---|
| 1 | zlib Z_NO_COMPRESSION / level 0 stored raw DEFLATE |
| 2 | zlib Z_HUFFMAN_ONLY, any level, 3-way block dispatch |
| 3 | zlib level 1 DEFAULT_STRATEGY |
| 4 | zlib level 6 DEFAULT_STRATEGY |
| 5 | zlib level 9 DEFAULT_STRATEGY |
| 6-11 | zlib levels 2, 3, 4, 5, 7, 8 DEFAULT_STRATEGY |
| 12-20 | zlib levels 1-9 Z_FIXED |
| 21 | zlib Z_RLE, collapsed across levels 1-9 |
| 22-27 | zlib levels 4-9 Z_FILTERED |
| 28 | Microsoft OOXML / Java `DeflaterOutputStream`: zlib L1 data blocks + `SYNC_FLUSH` + empty finish block |

Known collapses:

- Level 0 ignores strategy for raw stored output.
- HUFFMAN_ONLY ignores level for the DEFLATE body.
- RLE ignores level for the currently modeled behavior.
- FILTERED at levels 1-3 follows the deflate_fast path and collapses to
  default level 1-3 output.
- Several default levels produce byte-equivalent output for simple inputs; the
  identifier reports the first matching registry entry.

## Implementation Shape

Current modules:

- `src/bitstream.zig`: LSB-first bit writer and fixed-Huffman emit helpers.
- `src/huffman.zig`: zlib-compatible Huffman tree construction, canonical code
  generation, and code-length RLE.
- `src/match.zig`: zlib-style LZ77 tokenizers for fast, slow/lazy, filtered,
  and RLE strategies.
- `src/blocks.zig`: block cost calculation, stored/fixed/dynamic emitters, and
  multi-block dispatch.
- `src/encoder.zig`: public fingerprint encoder functions.
- `src/lib.zig`: registry, identify/encode APIs, and C FFI exports.
- `src/inspect.zig`: pure DEFLATE block-boundary inspector covering STORED,
  fixed-Huffman, and dynamic-Huffman block range reporting for the Excel
  boundary probe.
- `tools/zip_corpus_probe.zig`: ZIP-family raw-DEFLATE corpus probe.

The code still uses an inline registry rather than a separate registry data
format. That is acceptable for the current 28-entry research stage, but a
versioned append-only registry remains a v0.1/v0.2 hardening item.

## Recent Correctness Fix

`src/match.zig` has a zlib `MAX_DIST` fix committed in `zzvvlnuv`:

- zlib uses `MAX_DIST = window_size - MIN_LOOKAHEAD`.
- With default values, that is `32768 - 262 = 32506`, not `32768`.
- Accepting matches with distance 32507-32768 caused token-stream divergence on
  inputs larger than 32 KiB.
- The fix adds `maxDist(params)` and applies it in fast, slow, and chain-walk
  paths.

This is tested by the existing suite and was manually verified against a
46 KiB info-zip case before this checkpoint.

## Active Investigation

Excel `.xlsx` `xl/worksheets/sheet2.xml`:

- Raw size: 279,493 bytes.
- Excel compressed size: 52,876 bytes.
- Our current `encodeOfficeOPC` size: 53,419 bytes.
- Small sibling entries in the same archive match zlib L1 + OPC flush/finish.
- The large worksheet does not match zlib levels 1-9.

Open hypotheses:

- Excel changes level or memLevel for large entries.
- Excel uses a different block-boundary heuristic than zlib's default
  16,383-symbol pending-buffer split.
- Excel uses a non-zlib encoder for large worksheet XML.
- The large-entry encoder is a custom point between zlib L1 and L6 behavior.
